## 事实策略与审核语义

原始 bullet 必须在允许的冻结来源中逐字存在。伪造 ID、重复来源、新增数字和保守规则可识别的无来源公司/技术实体拒绝。实体规则不是完整事实证明：所有非原文建议都必须用户对照来源明确确认；未选建议保留原文。确认请求只能选择服务端候选索引，不能提交任意替换文本、来源或跨用户经历。

WAITING_REVIEW 不占编译容量，不自动编译。规划 SHA256 版本冲突拒绝；相同确认幂等，不同确认拒绝覆盖。规划和决策首次写入后 ORM 禁止改写，保存在文档快照；失败重试沿用原冻结经历、模板及确认结果。ai_status 描述调用状态，review_status 单独描述采用前的用户审核状态，不把人工确认描述为自动事实验证。

## 迁移及运维影响

新增 `resume_review_002`，在原运行迁移后增加 job.review_plan/review_decision、WAITING_REVIEW CHECK 和 resume_execution_slots。原 P1/P2/运行迁移、模板版本、历史文档与用户经历未覆盖。业务库未执行迁移；验证只使用用户明确提供的测试连接创建随机 schema。

API 与 worker 必须同时更新并迁移，否则不能识别新状态/字段。部署前停止相关任务写入并核实目标库。待审核无超时自动确认，用户可回到对应 job 页面恢复审核。指标增加等待审核、容量占用及待清理数。

连接锁与持久容量共同控制执行：锁丢失后取消，执行停止或资源清理未确认时槽位保持 CLEANUP_REQUIRED。登记 PID 与创建身份；旧进程仍活着时不能凭“锁已释放/容器尚不存在”释放容量，须等待旧执行结束确认或核实原进程已消失。Windows 使用只读有限进程查询，Linux 使用 /proc 创建身份；没有更改权限或终止其他进程。相同 PID 被复用时通过创建身份区分。固定槽位容器名提供 Docker 端互斥，任务标签仍独立核验，不能删除其他尝试的容器。

原主机相同配置的 worker 才能自动核实遗留资源；更改主机名、Docker context/host 或编译根目录会保守阻塞相应槽位。维护者须在原主机确认资源，不提供强制清空槽位的自动入口。进程身份无法核实时失败关闭；当前实现支持本次 Windows 开发环境和 Linux 编译目标，其他平台不宣称可用。

自动进程恢复要求后续 worker 能在同一主机/PID命名空间核实原进程。推荐 Linux 主机上的受控服务 worker 配合隔离的编译容器；不能将不同命名空间的 PID 当作同一进程。若应用 worker 自身容器重建导致 hostname/PID 命名空间变化，现有实现保守拒绝自动释放，需要运维核实，未宣称这种部署已验收。

回收先核实专用根目录、无链接、精确任务子目录和身份文件，再核验容器标签及不存在状态，最后仅删除 input.json、container.id、identity.json。未知文件、身份不符、Docker daemon 查询失败均保留并报警。重启可回收已登记但尚未创建容器的目录；不追溯清理本修复之前未登记的旧资源，它们需维护者另行核实授权。

数据库降级需要在线预检；存在审核记录或非 FREE 容量时拒绝。建议保留新增数据并回退应用前暂停相关写入口，不启用旧宿主编译。没有核实生产备份或生产回退演练。
