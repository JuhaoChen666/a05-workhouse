## 如何实现

复用 P1 的严格五类输入、owner 隔离 mapper、revision CAS、事务和私有文件机制。新增 API 请求/响应契约、认证 dependency、业务服务、数据库查询方法、PDF 提取器及可替换 AI 客户端。路由负责 HTTP 转换，服务负责业务与事务，mapper 负责数据库访问。

建议接口前缀 `/api/experiences` 和 `/api/experience-imports`，最终以契约文档和 OpenAPI 为准。客户端 user_id 不参与身份判定；公开人工输入不能借由 source_type/source_locator 伪造 PDF 来源，PDF 来源只由服务端确认流程绑定。

以下七步保留原设计说明；实际接口见 ../resume_phase2_api_contracts.md，实际验证及限制见 ../resume_phase2_handoff.md。

## 七步及验收

### 1. 确定基线、分支和业务契约

状态：完成，基线/分支/详细接口契约已核实并记录。

- 已核实 Issue、远端 master、P1 合并情况和工作区；从最新 origin/master 创建本地 P2 分支。
- 固定五类请求字段、分页和筛选规则、删除语义、错误码、批量原子性及草稿生命周期。
- 在开发前检查必要依赖、测试夹具、迁移入口和应用启动副作用；不自动运行全量 AI/模型初始化。
- 效果：P2 基于完整 P1，后续前端有一致接口规范。

### 2. 接入可信认证和 API 基础

状态：已实现，真实认证与路由配置单元验证通过。

- 优先直接校验兼容 Spring 的 Bearer JWT：固定允许的签名算法，校验签名/有效期及必要 claim，从可信 id 提取正整数 owner。
- 密钥通过必要服务器环境配置提供，不能复制到新代码或文档；缺少配置时明确失败，不回退为未校验 token。
- 注册 P2 路由，统一错误结构。401 认证失败、404 不存在/跨 owner、409 revision 或状态冲突、422 输入错误；依赖不可用提供稳定可解释错误。
- 保留旧链路，控制新增模块的导入和生命周期副作用。HTTP 测试必须使用实际新路由和真实认证校验，数据库/外部 AI 可通过明确依赖注入接入测试资源。
- 效果：服务端身份决定所有经历、草稿和来源文件的归属。

### 3. 完成五类经历 CRUD、分页、筛选和归档

状态：已实现，真实 MySQL/ASGI 业务验证待测试连接。

- 复用五类完整输入校验；首版使用完整替换编辑，避免误把 attributes 响应直接用于请求。分类不可变，PDF 来源追踪由服务器保留。
- 分页在数据库执行过滤/count/offset/limit；建议 page 从 1 开始，page_size 默认 20、上限 100。默认仅未归档，归档筛选提供 active/archived/all。
- 分类精确匹配；标签建议去首尾空白、去重，按精确且区分大小写的 all-of 匹配。多个筛选维度采用 AND。
- 关键词建议对 title、tags 和五类明确列出的可搜索文本属性做字面子串匹配；转义 SQL LIKE 通配符，不搜索 ID、owner、来源元数据。具体大小写规则及字段名单写入契约并验证 MySQL 行为。
- 稳定排序为 sort_order ASC、id ASC；返回 items/page/page_size/total。
- 编辑、归档/解除归档、排序统一比较 expected_revision，并递增 revision。删除建议条件删除当前经历记录，同样校验 owner/revision；不改写历史任务/文档快照，不直接删除来源文件。
- 效果：五类经历均可管理，组合筛选和分页正确，过期编辑不会覆盖新数据。

### 4. 完成排序和人工结构化批量导入

状态：已实现，真实事务验证待测试连接。

- 排序接受同 owner 的条目 ID、sort_order、expected_revision；拒绝重复 ID，逐项返回新 revision。
- 人工批量输入只允许 MANUAL，复用五类严格校验，不允许客户端提供服务器字段或伪造 PDF 来源。
- 批量入库与排序均按单批事务执行：全部成功或全部回滚；校验错误包含条目位置和字段路径。限制单批数量。
- 效果：批量维护可核对，无半批成功却响应全部失败的情况。

### 5. 完成 PDF 提取、AI 结构化及持久草稿

状态：已实现，真实 PDF 和确定性 AI HTTP 适配器验证通过，持久流程待 MySQL 验证；外部模型未调用。

- 支持上传 PDF 或选择同 owner 的旧 PDF；旧文件使用受控路径检查及记录 owner 校验，上传保存到 P1 私有文件存储。
- 基于 pypdf 逐页提取，保留页码及片段；设置文件大小、页数和文本量限制。区分文本可用、无可用文本/OCR 暂不支持、加密、损坏和其他提取失败，不将失败当作空成功。
- 新增 PDF 专用 AI 抽取适配器，只返回结构化草稿；允许缺字段/未知日期，标记待修正问题，不编造事实。非法 JSON/未知分类/模型不可用有明确错误。
- 建议新增两表：导入批次保存 owner、源文件、状态、错误、过期时间、确认请求摘要和结果；草稿条目保存 batch/owner、稳定 ID、候选内容、问题、定位和 revision。
- 追加 P2 增量迁移，保持 P1 001/002 原样，并扩展必要迁移元数据范围。
- AI 调用在数据库事务外执行；短事务记录处理状态和结果，处理超时或进程重启留下的处理中批次，避免长期持锁或永久卡住。
- 效果：PDF 先变成可读、可修正、可删除条目的草稿，服务器重启后仍可恢复；正式经历库尚无新增。

### 6. 完成显式确认、幂等和文件生命周期

状态：已实现，实际数据库/文件并发与故障验证待测试连接。

- 用户读取、修正和删除草稿条目，再提交选中条目 ID 及预期草稿版本；确认时重新完整校验最终内容和所有 owner/source 关系。
- 锁定批次，按单个数据库/私有文件协调事务创建全部经历，同时保存不可变确认回执和生成 ID；不嵌套 session.begin()。
- 同一确认重复请求返回原回执；同一批次使用不同选中条目/版本确认返回 409。并发确认只允许一次创建。已确认条目随后编辑/删除不触发重新入库。
- 建议批次状态 PROCESSING/READY/FAILED/CONFIRMED/CANCELLED/EXPIRED；条目有独立校验问题。建议未确认草稿保留 7 天，实际期限配置化。确认成功后不可再修改该批次。
- 取消、过期或失败按引用检查释放来源；活跃草稿、已入库经历（含归档）及 P1 历史文档/活跃任务共同保护文件。保留确认回执以支持重试核对。
- 补齐 P1 清理对新增持久草稿的引用保护及受限维护入口；不启动生产清理调度，不删除用户现有资料。
- 效果：确认前零正式入库，确认后来源可追溯，重试/并发不重复，失败整批回滚，来源不会被提前清理。
