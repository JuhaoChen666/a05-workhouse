# 差距核实与实现决策

2026-09-18 重新读取 Issue #1、PR #2/#3/#5/#4/#6 和远程 master。最新基线仍为 2b79ce9b2c1f1225a0b0f2024ed6414160ef996a；原本地 master 为 d24f5a3，仅安全创建新分支，未覆盖已有修改。

旧代码确认存在：手工模式调用 AI、模块顺序未渲染、页数/语言仅保存、宿主编译继承全部环境、BackgroundTasks 生成生命周期、文档管理缺少 document_id 闭环、经历前端未接持久导入/排序。因此在已有 P1/P2/P3 基础上补齐业务。

实现采用以下明确契约：

- 手工生成不调用 AI。AI 只能引用冻结的允许经历和真实原始 bullet；无法可靠验证的语义改写保留原文，虚构数字/伪造来源拒绝，调用失败显示降级。
- 语言控制规划和模板标题，事实正文保留来源语言；目标页数为实际 PDF 页数上限，超限失败且不保存文档。
- 新增两套 1.2.0 / 协议 1.1 模板，实际使用模块顺序；历史版本未改写。新版本 scoped -text 保持字节，初始化可只选择新版本，避免旧跨平台字节冲突。
- document_id 是文档操作/下载身份；复制共享输出仍独立管理。再次编辑从原冻结快照创建新任务，不读取已改变的经历事实。
- 历史 Markdown owner 隔离只读，主动生成先进入持久草稿和用户确认，保留旧正文，不作为新排版中间层。
- API/worker/初始化/维护使用同一显式数据库和私有文件配置。生成 API 和重试使用私有文件事务；真实 PDF 导入 E2E 曾发现缺少文件事务导致生成提交失败，已修复并回归。
- MySQL 任务锁、全局容量锁和 token 防重复执行；真正 worker 进程被本测试终止后，后续 worker 将孤儿标为中断，再按冻结输入重试。
- 隔离编译仅受信任不可变 Linux Docker 镜像，能力不足失败，不回退宿主。参数/超时清理测试不是真实容器安全验收。

可用环境验证包含真实 MySQL、JWT、文本 PDF 提取、确定性渲染和实际 worker 进程；AI 与成功编译是明确替身。真实 AI/容器/浏览器均是待验收项。
